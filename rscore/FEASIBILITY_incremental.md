# 增量计分可行性报告（2026-11-09）

> 问题：能否把导师的 13 状态 DP 做成**增量**（改一个叶子的颜色只更新祖先链），
> 从而让 ASTER2 的放置/NNI 不再每次 O(基因树)？
> 结论：**可行，预期加速 100–500×**；有两个前置条件（多叉 resolve、内存控制）。

## 1. 原理

13 状态 DP 在基因树上做后序：
`state(t) = step(state(l), state(r), edge(l), edge(r))`，根节点的 `state[12]` 就是
三色划分 (A,B,C) 的 2-1-1 可靠四叶树计数（= 我们 W/2）。

- 改一个叶子颜色 → 只影响它到根的祖先链（长度 = 树深）→ `O(深度)` 更新；
- 读分数 = `O(1)`（读根状态）。

## 2. 实测（rep16 的一棵真实基因树，Huffman resolve 成二叉，17999 节点、9000 叶、深度 17）

| 操作 | 耗时 |
|---|---|
| 整树初始化（一次后序） | **344 µs** |
| **单叶改色（增量）** | **0.63 µs** |
| 当前 `rscore` 的 W（6 次 F） | ≈ 1 ms/节点/基因 |

## 3. 物种树统计（`team01_rbuild.tree`，10000 叶）

| 量 | 值 |
|---|---|
| 内部节点 | 9999 |
| 子树大小：均值 / 中位 / 最大 | 19.8 / 3 / 6055 |
| Σ_v size(subtree(v)) | 197,580 |
| 单轮 NNI 需要重染的叶数（上界 2×Σ） | ≈ 3.95×10⁵ |

## 4. 预估速度

单轮 NNI（全部边 × 2 变体，1000 棵树，32 线程）：

```
3.95e5 叶重染 × 1000 棵 × 0.63 µs / 32 ≈ 7.8 秒
```

| | 现在 | 增量后（预估） | 加速 |
|---|---|---|---|
| 单轮 NNI | ≈ 1 小时 | **≈ 8–16 秒** | **250–450×** |

（C 边修正需要第二套状态，翻倍到 ≈16 秒；仍是 200× 以上。）

## 5. 两个前置条件

### 5.1 多叉必须 resolve
- 13 状态 DP 的 `step` **只对二叉节点成立**；直接对 k 叉节点做简单折叠会**多算**
  （实测：20 组多叉树 9 组不一致）；
- 导师的做法：Huffman resolve 成二叉，合成边标 `C`，同时跑两套 DP，
  答案 = `(V1 − V2)/2`（V2 扣除"用到 C 边"的四叶树）——**语义与我们的边判定一致**
  （已在 120 组随机用例上验证）；
- 代价：节点数 ×1.6（11164 → 17999），DP 计算 ×2。

### 5.2 内存
每基因每节点需要 13 个状态（×2 套 DP）：约 124 B/节点 →
1000 棵树 × 18000 节点 ≈ **2.2 GB**，偏大。
- 缓解：**搜索时只用 50–100 棵树**（≈ 110–220 MB），最终分数用 `score_fast` 全量算；
- 或：小状态用 int16/int32（叶子数 ≤ 9000、对计数 ≤ 4×10⁷），只有 Q/co 用 int64。

## 6. 关键风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 语义对齐 | resolve + C 边必须与"不 resolve 的边判定"逐值一致 | 已有 120 组随机对拍；集成后再全量对拍 3 个 rep |
| 内存 | 见 5.2 | 搜索用基因子集 |
| 实现量 | 需要实现增量 DP + 接入 ASTER2 的 colorable 接口 | 先在 500 类群做原型 |
| 框架调用模式 | ASTER2 的放置是按子树批量改色，成本 ∝ 子树大小 | 已在估算中计入 |

## 7. 建议的实现路线（原型优先）

1. **原型（2 天）**：独立实现"增量 13 状态 DP"（二叉 + C 边 + V1/V2），
   与 `score_fast` 对拍：任取一棵物种树、任取一个节点，比较 `W(u)/2` 与 DP 值；
2. **接入 ASTER2（2–3 天）**：写 `rscore_incr.hpp` 替代现有 `rscore.hpp`，
   在 500 类群上跑框架，测放置/NNI 墙钟；
3. **验收**：500 类群上与现有实现分数一致、速度快 ≥50×；
4. **全量**：10000 类群跑一次完整搜索，比较结果。

## 8. 结论

- **技术上可行**，而且收益很大（100–500×）；
- 前置条件是"多叉 resolve + 两套 DP + 基因子集控内存"；
- 建议先做 500 类群原型验证，通过后再集成到全量求解器。
