# 打分插入（Phase 2）设计草案

> 背景：修正为无根三分划口径后，全量四棵树彼此只差 0.003%，说明 NNI 已无空间；
> 瓶颈是初始构造。500 类群上「框架放置 + NNI」(2.535e9) 比「簇共识 + NNI」(1.889e9) 高 34%。

## 1. 原语与成本

- 节点分数 `W(A,B,C)`：6 次 `F`（每次 O(n) 扫描基因树），A/B 是节点两个孩子簇，C 是其余。
- **插入**类群 x 到位置 p（p 上方）时：p 到根的**每个祖先**的叶集合都变，它们的 W 都要重算。
  ⇒ 单个候选位置的评估成本 ≈ `depth × 6F × T'`。
- NNI 不受影响：交换保持 `subtree(u)` 不变，只有 u、v 两个节点变化（已验证）。

## 2. 算法

```
输入: 基因树集合；参数 T'(放置用基因数), C(候选数), m_b(骨架规模)
1. 选 m_b = ceil(sqrt(n·log2 n)) 个"最有信息量"的类群（按出现在小簇中的次数排序）
2. 骨架：这 m_b 个类群逐个插入，候选 = 当前树的全部内部边（规模小，可以全评估）
3. 其余类群逐个插入：
     候选 = { 伙伴 LCA 节点到根的路径上 depth 个节点 } ∪ { 伙伴 LCA 的两个孩子 }
     每个候选用 T' 棵基因树精确算 ΔW（沿祖先链），取最优
4. 全量 NNI 精修（1000 棵树），到收敛
输出: 物种树 + 分数
```

其中"伙伴"= 在基因树小簇（size 2..50）中与 x 同簇的类群；在树上取它们的 LCA 作为锚点。

## 3. 成本估算（10000 类群 / 1000 棵树）

| 阶段 | 计算量 | 32 线程估计 |
|---|---|---|
| 骨架（365 类群，全候选，T'=8） | ~1.6e12 | 20–40 分钟 |
| 插入（9600 类群 × 8 候选 × depth≈10 × 6F × T'=8） | ~4.2e11 | 5–15 分钟 |
| NNI（1000 棵树，2 轮） | 每轮 ~1 小时 | 1–2 小时 |

## 4. 验收

- 500 类群上与修正后框架基准（2.53e9）对标：目标 ≥ 90%；
- 全量：与当前 1.5986e15 对比；
- `verify.sh` 与根重挂回归必须继续通过。

## 5. 风险与备选

- 候选限制太狠 → 质量掉；备选：候选数翻倍 / 让"伙伴 LCA 子树内的兄弟边"也入选。
- 骨架基因数太少 → 骨架错；备选：T' 升到 16，成本线性增加。
- 若整体收益 < 5%，说明当前瓶颈不在构造，转而在"多叉 polytomy 的处理语义"。

## 6. 原型实测（2026-10-21，500 类群 / 100 棵树）

| 方案 | 初始 | NNI 收敛后 |
|---|---|---|
| 簇共识 + NNI | — | 1,888,878,746 |
| **打分插入（T=6, cand=6, budget=100）+ NNI(40)** | 1,534,604,254 | **1,935,124,107** |
| aster2 框架放置 + NNI（旧目标树，新口径打分） | — | 2,534,824,702 |
| aster2 框架放置（新口径重跑） | 超过 15 分钟仍未完成 | — |

- 插入版只比簇共识好 **2.5%**，离框架的 2.53e9 还差 24%；
- 放宽参数（T=20, cand=12, budget=300）后 500 类群要跑 >10 分钟——**当前实现太慢**，
  瓶颈是每个候选都要重算祖先链上的"旧 W"（每个祖先 6 F × 2）。

## 7. 下一步（按收益排序）

1. **缓存每个节点的 W**（现在每次候选都重算旧值）：插入后只更新路径上的节点，
   候选评估只算"新值"，成本减半；
2. **剪枝**：只评估 `sz[p] ≤ 阈值` 或与 x 的伙伴集合有交的候选；
3. 候选集扩大（框架相当于"全部边 + 100 棵树"），用更多基因只评估 top-k 候选（两阶段）；
4. 目标：500 类群上 ≥ 2.3e9，再上全量。

## 8. 实测更新（2026-10-21 晚，500 类群 / 100 棵树）

| 方案 | 初始 | NNI(40) 后 | 构建耗时 |
|---|---|---|---|
| 随机树 | 1,700,696,637 | 1,774,771,175 | — |
| 簇共识 | — | 1,888,878,746 | 秒级 |
| **builder（budget=60,cand=4,genes=4）** | 1,742,679,441 | **2,360,511,229** | 2.3 s |
| builder（budget=120,cand=6,genes=8） | 1,742,739,275 | 2,351,770,883 | ~10 s |
| 框架 + NNI | — | 2,534,824,702 | 分钟级 |

**重要发现**：
- builder 产出的树最大深度 **336**（接近毛毛虫），说明**候选 Δ 几乎全为 0、退化成"按顺序挂到根"**；
  真正起作用的是**插入顺序（按频率）** + 后面的 NNI。
- 但即使如此，它 + NNI 已经到框架的 **93%**（2.36e9 vs 2.535e9），远好于随机树 + NNI（1.77e9）。
- 结论：**下一步的关键不是更快的评分，而是修掉"Δ 恒为 0"**（小树时补集为空、W 几乎都是 0）。
  可选做法：插入时用"子树内部结构"的代理分数（如 F 的孩子簇对），或在树稍大后再开始打分决策。

## 10. 三分划并集重组（recombine.cpp，2026-10-21）

做法：把 K 棵物种树的所有 cluster 收集成 DAG（候选 split 只取输入树里真实出现过的），
按 cluster 大小 DP：`best[X] = max over splits (A,B) of best[A]+best[B]+W(A,B,~X)`，
最终 `score = best[全集合]/2`。

**验证**：DP 分数与 solver 对这棵输出树的独立打分**逐值一致**（2,510,579,533）。

| 输入 | DP 分数 | NNI 后 |
|---|---|---|
| 8 棵随机顺序 builder + NNI（2.33–2.41e9） | 2,413,257,099 | 2,413,257,099 |
| 上面 8 棵 + 簇共识 + 框架树 | 2,510,596,951 | **2,534,903,521** |

结论：
- 重组**不会比最好的输入差**（它包含每个输入的 split），但**收益取决于输入多样性**；
- 我们自己的构造都在 ~2.4e9 的同一个盆地，重组只能取到最大值；
- 加入框架树（2.51e9）后，重组 + NNI 到 2.535e9（= 框架 + NNI 的水平）。

## 12. Builder 增量评分修复（2026-10-27）

修正 `rscore/solver/builder.cpp` 的候选增量计算与 bitset 状态：

- 第二个 taxon 的叶 bitset 写入必须带节点偏移；
- 新节点 `(p,x)` 的两侧是 `p` 与 `{x}`，不能把 `p∪{x}` 与 `{x}` 当成两侧；
- 部分树的第三份必须取 `activeMask & ~(A|B)`，不能把尚未插入的 taxon 计入；
- 插入一个 taxon 会让**所有现存内部节点**的外部分区 C 增加该 taxon，不限于 p 到根路径；旧修复版因此逐候选重算所有旧节点，并在提交后全量刷新缓存。
- `builder_selftest.cpp` 在 10 taxa / 3 棵含 S/D、多叉及缺失类群的基因树上，对 80 个候选插入逐一比较旧 `candidateDelta` oracle、批量公式、完整 `ΣW` 重算和独立四叶树枚举；同时比较增量缓存提交与旧全量刷新，全部一致。
- selftest 还检查每个候选的增量非负且为偶数，并比较增量提交与完整刷新得到的拓扑、bitset、子树大小和缓存。
- 40 taxa smoke 输入上 builder 的独立 C++ / Python 分数一致（89,728）。

**性能复测（2026-10-31）**：同一 500 taxa × 100 genes 输入、8 线程、`--budget 60 --cand 4 --genes 4`，旧版（HEAD）与最终批量版相邻运行各一次。旧版 9.48 s / 5,740 KiB RSS；批量版 2.86 s / 6,156 KiB RSS，约 3.3× 加速。两版输出 Newick 逐字相同（SHA-256 `1b086775e6eabffa6c9d9cadb5573c31a3d7a36b089e27de166a43629e1e354f`）；完整 100 棵树 C++ 与 Python 分数均为 1,747,614,212，随后全量 NNI 均为 2,357,934,671。该性能结果是单次受控对照，仍需重复测量后再外推全量耗时。

实现路径：

1. 对每个旧内部节点 `v` 一次算出 `dA/dB/dC`，分别表示插入叶 `x` 到左子簇、右子簇、外部补集时该节点 `W` 的变化；候选位置新增节点另算 `N[p]`。
2. 令 `base = Σ_v dC[v]`，沿树传播 `prefix[child] = prefix[parent] + dDirection[parent] - dC[parent]`，候选总增量为 `base + prefix[p] + N[p]`。
3. 提交前保存最佳候选到根的旧方向；旧节点缓存先加 `dC`，严格祖先再修正到对应 `dA/dB`。新内部节点直接设为 `N[p]`，不再全量重建缓存。
4. 旧 `candidateDelta` 与全量缓存刷新保留在 selftest 中作为 oracle。DSU 重着色以及通用 batch placement DP 暂不进入生产路径。
