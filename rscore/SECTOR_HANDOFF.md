# 扇区（sector）方法：交接摘要

> 给主会话看的现状与结论。细节与全部验证记录见 `rscore/SECTOR_MATH.md`。

## 1. 一句话结论

**扇区方法现在可用且经过逐值验证**：对每个叶子，它给出"重挂到任意位置"的**精确**得分变化，
可以拿到该叶子的**全局最优位置**（不是随机采样）。全量（10000 类群 × 1000 基因）跑一轮
约 **9 分钟**，5 轮共 **+0.0791%**；在 500 类群上从 NNI 树出发拿到 **+2.64%**。

## 4. 推荐流水线

```
共识 → NNI → 【扇区 2–3 轮】 → SPR（去掉单叶移动）
```

* 扇区负责"单叶全局最优"——这是 SPR 随机采样做不到的；
* **SPR 里的 `--leaf` 单叶移动因此不再需要**，它只做内部边 SPR 会快很多；
* 两者的分工：扇区把单叶空间榨干，SPR 负责大的拓扑重排。

## 5. 工具与命令

```bash
# 相位 1：一次遍历算出全部 (m, 叶子, 方向) 的 T 表（O(nK)）
sector_sweep --species TREE --genes GENES --strategy m \
             --threads 256 --m-count 100000 --dumpbin /local/T.bin
# 相位 2：换根求每个叶子的最优挂载位置，应用前 K 个
sector_place --species TREE --Tbin /local/T.bin --apply 200 --out NEXT.tree
# 精确复核（权威口径）
solver -s NEXT.tree -i GENES -t 32 --sweeps 0
```

* 单轮 352 s（相位 1）+ 约 180 s（相位 2 与复核）；
* T 表 2.4 GB，**必须写节点本地盘**（`/tmp`），不要写 NFS；
* 提交脚本：`/nfs/hot/chenzz/relquartet/scripts/rq_sector.sbatch`
  （`--qos=half` 要求**正好 240G 内存**、256 CPU）。

## 7. 已知限制 / 下一步

1. **多移动同时应用会轻微过冲**（Δ 是在同一快照上算的）：靠"应用后用权威评分复核、
   不涨就回滚/换更小的 K"来处理，已实现。
2. 相位 1 的并行标度在 ~16–32 线程就饱和（内存带宽），256 核只有 6× 左右的效率；
   35 ms/m 已是当前实现的水平。想更快只能减常数（当前每节点约 60–100 次操作）。
3. 还没有做"两叶同时移动"或"子树重挂"——这是下一步可挖的空间。
