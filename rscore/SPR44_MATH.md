# spr44 移植到"可靠四叶树"目标：数学推导与路线

> 目标：像 ASTER 的 `spr44` 那样，**对每个候选剪枝子树求出它的最优重挂位置**，
> 结论（2026-11-19）：已推导出**逐位置精确**的 O(n²) 公式并通过真实数据对拍（残差 0），
> 见第 2 节与第 9 节；尚未接进搜索循环。

## 1. 记号

- 物种树 S（二叉或近二叉），内部节点 z 的三分划 `(A_z, B_z, C_z)`
- 节点分数 `W_z = 满足 (A_z,B_z,C_z) 的 (2,1,1) 可靠四叶树个数`
- 总分 `score(S) = (1/2) Σ_z W_z`
- 待移动子树 `A`（叶子集合 `L_A`），旧父 `p`，祖父 `g`，兄弟 `sib`
- 目标边 `e = (u, v)`，`B_e = subtree(v)`，`C_e = 其余`

## 2. 精确分解（2026-11-19 修正版）

> 旧版"引理 1"（Δ = Δ_old + Δ_new，两段和都在 S 上算）**是错的，已废弃**。
> 错因有两层：(a) 旧路径与新路径重合时，重合节点的增量被用两个不同基准各记一次；
> (b) 更根本的是把"摘掉 A 的树"和"原树"的 W 混在一张表里（rest 集合不一致）。

正确做法：以 **T2 = S 摘掉 A（并抑制单父节点）** 为唯一骨架，所有 W 都在 T2 的叶集上取。
记 X = A 的叶子集；T2 中节点 z 的孩子为 (c1,c2)，`rest_z` = T2 中 z 之外的类群。

对 T2 的每个内部节点 z 备好两个数：

```
V_z     = W(c1, c2, rest_z ∪ X)          X 放在 rest 里   → 路径外节点在 S' 里的取值
Wa(z,c) = W(c ∪ X, sib_c, rest_z)        X 并入路径孩子   → 路径上节点在 S' 里的取值
W_w(e)  = W(X, sub(v), rest_u ∪ sib_u)   新节点 w 的值
```

A 的每个内部节点 a 的三分划与挂点无关（rest 恒为 A 之外的类群），直接取原树值 `W_a(S)`。

则对任何挂载边 e = (u,v)（u = par(v)）：

```
2·score(S') = Σ_{a∈A 内部} W_a(S) + W_w(e) + Σ_{z∈T2} V_z + Σ_{z∈path(u→root)} [Wa(z,c_z) − V_z]
```

末尾一项是沿根路径的前缀和，一次 DFS 得到，每个位置 O(1)。

**证明**：S' 的节点 = T2 的节点（路径上换值）+ 新节点 w + A 的内部节点。
- 路径外的 z：S' 里 X 落在 z 的 rest 中 ⇒ 值就是 V_z；
- 路径上的 z：S' 里 X 并入路径孩子 ⇒ 值就是 Wa(z,c_z)；
- w 给 W_w；A 的内部节点给原值。
先把全体按 V 计一次（Σ_{z∈T2} V_z），再把路径上的换成 Wa（减去 V），三项相加即得。∎

**代价**：每个候选 A 只需 O(n) 次 W 求值（V 一遍、Wa 一遍、W_w 一遍，各 n 次）。
全轮从 O(n³) 次 W 求值降到 **O(n²)**。

## 3. 朴素做法为什么太慢

```
每个候选子树 A：n 个候选边 × 每边 O(路径长 d × 基因数 G × 基因树大小 |g|)
⇒ 单轮 O(n² · d · G · |g|)     n=1e4 时约 1e19 ✗
```

我们现在的 `spr` 正是这条路线的随机采样版（每次采样一次 O(d·G·|g|)）。

## 4. ASTER 为什么只有 O(n²)

`spr44` 对每个候选 A 做**一次物种树 DFS**，用"阶跃着色"：
沿 DFS 走一条边时**只有 O(1) 个叶子的颜色变化**，
而 `elementScore()` 是**根状态 O(1) 读取** ⇒ 每个放置位置 O(1)。

```
每个 A：O(n) 次放置 × O(1) 读分 = O(n)
全轮：  Σ_A O(n) = O(n²)                     ✓
```

关键不是"更快的单点计算"，而是**改色后全局分数自动更新**——
不需要像我们那样重算"新位置到根"的整条链。

## 5. 我们的目标能否做成 colorable？

能。我们的分数也是"基因树上一次 DP 的根值"：

```
W_z(g) = V1[root][12] − V2[root][12]（13 状态 DP，见 rscore.hpp）
score  = (1/2) Σ_z W_z
```

`rscore_incr.hpp` 已经把它接到 ASTER2 的 colorable 接口：
- `elementSetTaxonColor`：单叶改色 **0.63 µs**（基因树深度 17 时）
- `elementScore`：读根状态 O(1)
- 正确性：70 类群 × 50 树 = `score_fast` ✓；rep16 全量 = `score_fast` ✓

⇒ **基础设施已经存在**，缺的是把 `spr44` 的搜索循环接上去并测一轮的真实耗时。

## 6. 复杂度预算（2026-11-19 实测更新）

旧表里的估算（"每位置 O(G) 次改色 → 17 h"）基于错误模型，作废。实测：

| 方案 | n=80 全扫（78 子树 × 11138 位置） |
|---|---|
| 每位置构造树 + 整树打分（旧） | 37.4 s（∝ n³） |
| **本公式**（V / Wa / W_w 各一遍） | **1.32 s**（∝ n²） |
| 目标（增量改色，每次 W 求值 O(1) 读根值） | 待做，理论再降 1~2 个量级 |

按 n² 外推：n=1000 时全扫 ≈ 200 s；n=1e4 时 ≈ 5.5 h（单线程）。
所以有两种用法：
- **骨干版**：在 m≈300–500 的骨干上跑穷举 spr44（m² 次，秒级），其余类群放置回去 → 立即可用；
- **全量版**：需先做增量改色把单次 W 求值降下来。

## 8. 已知风险

1. `rscore_incr` 的 `elementScore` 需要**每个物种节点**都有状态
   （内存 ≈ 节点数 × 基因数 × 13 × 4B；10000 × 100 × 13 × 4 = 52 MB ✓ 可行，
   但 1000 棵树 = 520 MB ✗ → 搜索时用 ≤100 棵，最终用全量复核）
2. 骨干选择会决定能触达的拓扑空间（与 ASTER 相同的局限）
3. 我们的"可靠"条件使 DP 状态比 ASTER 的四分划分数更重，
   需要用 M1 先确认常数

### 连带修掉的三个坑

1. **裁剪工具把标号拼到叶名后面**：`tools/prune_trees.py` 在抑制单叉节点后把 `D` 接到叶子名上，
   `1129` 变成类群 `1129D` → 40 类群的数据被当成 57 个类群，分数虚高 7%（17642 vs 16491）。
   已修：叶边一律按 solid 输出，不再拼标号。`rscore.hpp` / `rscore_incr.hpp` 也顺带做了防御性剥除。
2. **旧的 20 类群夹具是假夹具**：`g20d.trees` 的基因树全是星形（无内部边），
   任何四叶树都不"被显示" ⇒ 分数恒为 0，逐位置比较变成 0 == 0。
   已删除，改用 `rscore/testdata/real40.*`（rep01 裁剪的真实基因树）。
   —— 之前所有"小树 0 误差"的结论都基于这个假夹具，作废。
3. **`score/2` 的整除截断**：Σ_z W_z 可能为奇数（根节点 rest=∅ 使部分四叶树只记一次），
   `/2` 会丢半格。所有比较一律在 **2×score 尺度**上做。

### 还剩下的常数：能不能再降

每位置 O(1) 的"纯算术"闭式**不存在**：W 是整棵基因树上的泛函（数的是全树四叶树），
不可能由局部数据 O(1) 求出。所以位复杂度下界就是"每个候选子树 O(n) 次全局求值"。
再往下只能压常数：

1. 一次四色 DP 同时给出 V / Wa / W_w 三个值，省掉重复扫描（常数 3 → 1.5 量级）；
2. 沿 DFS 增量改色：换一个叶子的颜色只需 O(基因树深度)，把每次 W 求值从 O(G·|g|) 降到 O(1) 读根值
   —— 这是 ASTER 的量级，也是全规模（n=1e4）唯一可行的路线。
