# 踩过的坑（勿重复）

## 计分/语义
1. **P0（2026-10）**：旧的"rooted 2-2 分家"计分漏掉四叶树且根依赖；已改为三分划 W 公式。
   **推论：任何 2-2 支持度分解都不能用于本目标**（框架 NNI 因此不可用）。
2. 多叉基因树**不能**简单 fold 或 resolve 后按 2-2 计数（会多算）；
   正确做法：Huffman resolve + 合成边 `C` + 两套 DP 相减（导师做法，已对拍）。
3. 缺类群：物种树的类群在基因树中缺失时，必须"不参与计数"；导师的程序曾因此直接崩。
4. 四叶树**无根**：根重挂不变性是回归测试。

## 第三方工具
5. ASTER2 的 `huffman()` 在单叉节点上崩；ASTER v1 的 ASTRAL-IV 在含单叉节点的数据上 segfault
   → 先 `splice` 单叉节点（去掉只有一个孩子的内部节点）。
6. ASTER2 的 NNI 用 2-2 支持度，与我们的目标不匹配（实测 −10.5%），**勿启用**。
7. 导师的 `solution_fast.cpp` 在缺类群时抛 `out_of_range`；读文件对 CRLF 敏感
   （`;\r\n` 会被解析成单叶）→ 需要 `readAllLines` 剥离 `\r`。
8. `substr(pos, len)` 不是 `substr(pos, end)`——原型曾因此把叶名解析错，全部分数变 0。

## 工程
9. 后台任务用 `nohup ... &`；不要用 `pkill -f <包含自己命令行的模式>`（会杀掉自己的 shell）。
10. 电池模式下 CPU 降频可达 3 倍，长任务务必插电；跑之前 `uptime` 看负载。
11. `./verify.sh` 是唯一可信的回归入口；改任何计分相关代码必须跑。
12. 长会话会显著拖慢推理：每个子任务新开会话，先读本目录。
